# Changelog

Notable changes to Lumen. Versions follow the tags on GitHub; downloads are on [Releases](https://github.com/emah-maker/lumen/releases).

## Unreleased

- **The sidebar no longer jumps to another tab's chat.** A full-page chat open in another tab (New tab, Ask AI) that started a new chat, opened one, edited a reply or began a run used to redraw the sidebar of the tab you were on as that chat, with your unsent text gone, while Lumen still thought the sidebar showed your own chat. Lumen now sends such an update to the sidebar only when the sidebar shows that chat (or the chat it showed is gone). New test: `test/sidebar-stays.js`, which keeps a long run going in one tab while you type in another (also registered in `scripts/test-all.js`).
- **Outside agents spend fewer tokens on Lumen's tools.** Over MCP, a nav, footer or sidebar in the compact outline shows its first 15 lines and a count (`find` still reaches every link), a cookie banner keeps its buttons but not its sentence, a `since_last` diff lists at most 25 added lines, and `navigate` no longer repeats the title and address in the page head. `list_tabs` rows leave out `active:false` and `group:null` and cut long titles and addresses, `read_tabs` reads 3,000 characters per tab by default (`max_chars_each` for more), and `hover` no longer adds a hint. A compact `read_page` now caps at 4,000 characters by default (it said where to continue, with `start_line`, and `find` reaches the rest; it was 6,000). Screenshots are 720 px wide by default (the same change as #536). `node scripts/mcp-token-report.js` measures what each tool costs on local pages (`--compare` shows before and after); new tests: `test/mcp-tokens-units.js`, plus checks in `test/efficiency.js` (which skips its Wikipedia and httpbin part with `LUMEN_TEST_OFFLINE=1`).

## 0.5.40 (2026-10-16)

- **EMF and WMF pictures in PowerPoint decks now show.** The slide viewer used to leave a placeholder and a banner ("Some pictures are in a format Lumen cannot show") for them. It now draws them with EMFJS and WMFJS (from rtf.js, MIT, about 55 KB each), loaded only when a deck has one, inside the slide page (no network, no access to the rest of Lumen), never in the main process. A file is checked first (size, record count, bitmap sizes), drawing has a time limit, and a picture that cannot be drawn (a damaged file, or an EMF+ that holds only GDI+ records) is a labelled placeholder of its own size; the banner appears only then. Covered by `test/pptx-images.js` (pixels, banner, and truncated or garbage EMF and WMF files) and `test/pptx-images-units.js`.

## 0.5.39 (2026-10-16)

- **0.5.38 was never published** (its macOS build stopped on a test that compared /var and /private/var as different folders); this release carries its changes, below.
- **Updates no longer fail with "files were in use" because of a program Lumen started.** Lumen was started from its own install folder (the Start-menu shortcut's "Start in"), so Microsoft Teams (opened from a msteams: link), the app that opens a downloaded file, or an AI assistant inherited that folder as its working directory, and Windows kept the folder locked, and the update unable to swap it, for as long as that program ran, often days. Lumen now leaves the install folder as it starts, and nothing it starts keeps one. If an update still finds the install in use, the message names the program (for example "close Microsoft Teams and try again").
- **The screen no longer flashes in your accent colour (purple, with the Purple accent) while the AI works.** The frame that shows the AI is working was the colour of the whole page area, so each time the page view was hidden, resized or not yet painted (a tab the AI opened, a page it loaded, a sidebar move) the whole area flashed. The page area keeps its own colour now and the frame is a thin 2 px ring that fades in once when the AI starts and out once when it finishes; it no longer blinks while the AI opens or switches its own tabs, and it only goes when you have looked at another tab for over a second. The small ring that marks where the AI clicked stays a moment without fading when Reduce motion is on. Test: `test/ai-drive-flash.js` (samples the window during five AI actions).
- **"Restart to update" now works while an AI assistant is connected to Lumen.** Claude Code, Codex and other apps set up with "Let other apps use Lumen" keep a copy of `Lumen.exe` running from Lumen's install folder, and Windows refuses to rename a folder with that running, so the update failed with "files were in use" and the old version came back. When the folder can't be renamed, the update now swaps the files one by one (a running exe can be renamed aside), puts everything back if a step fails, and deletes the old files at the next start. The error text also names the cause. If you are stuck on 0.5.35 or earlier, quit every app that uses Lumen (Claude Code, Codex) and click Restart to update once; later updates no longer need that.

## 0.5.37 (2026-10-16)

- **When the AI mentions a tab, the chat shows it as a chip you can click.** The chip has the tab's icon and current title (cut with an ellipsis; the full title and address are in the tooltip) and switches to that tab, in whichever window it is: the window comes to the front, and a tab the AI opened that **Hide tabs the AI opened** keeps out of the strip shows while it is in front. Chips appear in the AI's own words (it is asked to write `[[tab:ID]]` for a tab, a short line in its instructions), in the steps that name a tab (switching to, closing, reading, grouping, a screenshot of a tab, a tab it opened) and on the Browser card for the tab it works in. Titles follow the tab as it loads, with no polling. A tab that closed keeps its last title, struck through, and clicking it opens its address again; one with no web address is greyed with a tooltip. Saved chats keep each tab's id, title and address, so a reopened chat shows chips (from an earlier run of Lumen they read as closed tabs, never as whichever tab has that number now), and Export chat and the project folder write a chip as "Title (address)". A web page can never make a chip: anything a page or tool result says has `[[tab:` made harmless before the AI reads it, and only the AI's reply text (not code, links, your messages or step details) is read for markers. A button for keyboards and screen readers ("Switch to tab: Title"). Tests: `test/tab-chips-units.js`, `test/tab-chips.js`.
- **A Files card for the new-tab page, and `Ctrl+Shift+F` to find any file.** The **Files** widget (Add widget, under Work) lists the files and folders you pinned, then the last dozen local files you opened in Lumen, each with an icon for its kind, its folder and when you opened it. Click one to open it in a tab (a folder opens in File Explorer); right-click for Open, Show in folder, and Pin or Remove from Files (Unpin on a pinned one, with a few seconds to undo). A file that was moved or deleted turns grey and says "moved or deleted", with a **Find it** button that looks near its old place and lets you pick the match. Pin with the + on the card, **Pin to Files** on a file tab's menu, or from a download. **`Ctrl+Shift+F`** (also File > Open a recent file) opens a picker over any page: fuzzy search over pinned files, recent files and what is inside your pinned folders, with the matching letters marked; Enter opens, `Ctrl+Enter` shows the file in its folder, `Alt+Enter` attaches it to the sidebar chat. Lumen keeps only paths, names, sizes and times (never contents), encrypted, at most 500. Settings > General > Files has **Remember files I open** (`filesRemember`, on by default) and **Clear Files list**. A search with no match offers **Search Documents, Desktop and Downloads**, and a new profile's new-tab page starts with the Files card. New tests: `test/files-widget.js`, `test/files-picker.js`, `test/files-perf.js`.
- **"Get my chapter 4 slides": the AI finds files you use without searching the disk.** `list_files` takes a new `find` (a name or a description). It looks first in your Files list (pinned and recently opened files) and in your pinned folders, which Lumen has already indexed, so a file you use often is found in well under a second; only a miss searches your Desktop, Documents and Downloads (once, bounded, and only with Settings > AI > **Let the AI use files on this computer** on), and the file it finds that way is added to the list so the next ask is instant. Files the AI opens, reads or makes also go on the Recent list, and a download you open does too (**Remember files I open** turns all of that off). The folders you pin are indexed in a background thread (four levels deep, 20,000 files a folder, again every 10 minutes), never on the one that draws the window, and a missing file is noticed by looking, at most every five seconds. New tests: `test/files-store-units.js`, `test/files-fuzzy-units.js`, `test/files-index-units.js`, `test/files-ai.js`.

## 0.5.36 (2026-10-15)

- **A PDF a web page opens from a blob: address draws its first page without a scroll, and the page can open it.** A web app that builds a PDF (Canvas, for one) and opens it with `window.open('blob:…')` used to get nothing at all: Lumen refused every blob address. It now opens a tab when the blob is one the opening page made (same site); another site's blob and `blob:null` are still refused. PDFs shown by Chromium's own viewer (blob and other addresses it renders) are also asked to draw again when their tab comes to the front, when the view is resized and when the window is restored, for a viewer whose page area stayed grey until a scroll. Only PDF tabs do this. Tests: `test/pdf-blob-paint.js`, `test/pdf-repaint-units.js`.
- **Connectors: the AI can use Canvas, Gmail, GitHub, Todoist and more, once you connect them.** Settings → You and AI → Connectors is a gallery of cards (Mail and calendar, School, Files and docs, Work, Tasks, Music), each saying what the AI can read and do, with a state and one Connect button. Canvas uses the sign-in you already have in Lumen (it finds your school's address); Gmail uses Google sign-in (unread mail through the Google sign-in in Lumen without it); Google Calendar takes its secret iCal address; GitHub, Todoist and Notion take a token you paste, stored encrypted and never shown again; Slack and Google Drive are shown as coming soon. The AI gets one `connector` tool that lists only what is connected ("what's due on Canvas this week", "summarize my unread email"), in the sidebar and the full-page chat (also in the chats of the command-line engines Lumen starts itself, never for outside agents over MCP); steps read "Using Canvas · Upcoming assignments". Reads run at once; anything that changes something, like adding a Todoist task, always asks first and needs a real click: no Always allow, and Bypass permissions, agents that don't ask and hands-off mode don't answer it. Disconnect deletes the token. See [Connectors](docs/connectors.md). Tests: `test/connectors-units.js`, `test/connectors.js`.
- **The AI can use other apps on your PC, and the chat shows it working.** On Windows it can read and operate programs such as Word, File Explorer or MATLAB through Windows UI Automation. It asks before each app (**Allow for this chat**, **Always**, **Don't allow**), a banner at the top of the screen shows "The AI is using Word" with a Stop button, holding Esc or pressing Ctrl+Alt+Esc stops it, and touching the app yourself pauses it. A **Computer** card in the chat shows the app, what it is doing and a live thumbnail. Password fields, Windows security prompts, password managers, banking apps, terminals (unless you allow them) and Lumen itself are never available. Off by default: **Settings → AI → Let the AI use other apps on this computer**, with **Also allow terminals** and the list **Apps the AI can use** (Revoke). Tests: `test/desktop-units.js`, `test/desktop-apps.js`. See docs/desktop-apps.md.
- **Other apps can see and control Lumen, safely.** Settings → AI → **Let other apps use Lumen** (off by default; on already if you had agent connections on) sets up Claude Desktop, Cursor, VS Code and Claude Code with the exact text to paste, a Copy button and, where the path is standard, *Open the config file*. **Add app** makes a token of its own for each, kept encrypted and in a file only you can read, which the pasted text names (it holds no secret; the text warns against project files you would commit), and a new app asks before it acts by default; the list shows who is connected and when each was last used, and **Revoke** cuts one off at once. While an app works, a toolbar pill says "Claude Desktop is using Lumen" with **Stop** and **Take over**, its tabs say "Opened by Claude Desktop", and a quiet notification says when it finished. **Require a token for every app** is on for new users; for someone who already had agent connections on, an app without a token is an "unverified app" that waits for your Allow each time (per session, never remembered, always asking before it acts, and unable to use the name of an app you set up). The Lumen a bridge starts no longer inherits the app's token. Site permissions, AI-off sites and approvals apply as for Lumen's own AI, and Lumen's own pages stay out of reach. New `externalAppsRequireToken` setting and `docs/external-apps.md`; tests `test/external-apps-units.js` and `test/external-apps.js`.
- **You can add images to the new-tab Ask AI box.** In Ask AI, paste a picture (Ctrl+V), drop one on the box, or use the paperclip button at its right; each shows as a small thumbnail with an x (Backspace in the empty box removes the last one). Up to 10 images, 25 MB each, the same as the chat. Adding one in Search mode switches the box to Ask AI ("Images go to Ask AI"). Enter opens the full-page chat and the pictures are sent with your first message. The question and pictures now go to the browser through a narrow call from the new-tab page (a new preload that only that page gets), and no longer travel in the page address.
- **The AI's steps read in plain words, and its work shows as cards in the chat.** A step says what it is doing ("Reading p2.png", "Running pdf2png.ps1", "Writing fmt.ps1") instead of the raw command; click a step to see the exact command and its output, repeated steps fold into one row ("Read 4 pages"), a failed one reads "Couldn't read p2.png: the file was empty", and passwords and tokens in commands are masked. Work in a browser tab shows a **Browser** card with a live picture of the tab ("Working · Find lab TA", then "Done"), and **Open preview** takes you to that tab or opens its page again if it was closed; shell work shows a **Computer** card. Light graphics refresh the picture only when the page changes. The same in the sidebar and the full-page chat.
- **Pictures in PowerPoint decks draw the way PowerPoint draws them, and big decks open without a stall; a PDF no longer waits for a scroll to draw.** The slide viewer now handles tiled picture fills (they were stretched), picture fills with a crop or a fill rectangle, SVG pictures (the SVG is drawn, not its PNG fallback), transparency, grayscale, black and white, brightness, contrast and duotone, pictures in table cells, pictures cropped to an ellipse or rounded shape, links on pictures, pictures inside rotated or flipped groups, and a crop on a flipped picture. EMF and WMF pictures show a labelled placeholder naming the format. The same picture stored under several names is sent once, each picture is one shared image (very large ones, over about 3600 pixels, are shrunk for display), pictures load lazily, and a deck's pictures are sent to the page one slice at a time, so a 60 slide deck with 100 pictures opens with no main-process stall over 20 ms and no page task over 100 ms. In the PDF viewer, the view now draws the pages in sight whenever it gets a size, comes to the front or the window is focused (a PDF opened in a tab that had no size yet could stay blank until the first scroll). `test/pptx-images.js` and `test/pptx-images-units.js` check pictures by DOM geometry and screen pixels; `test/pdf-first-paint.js` checks the first page of a PDF is on screen with no input.
- **Ctrl+Enter means one thing: send what is in this box now, and the Keyboard Shortcuts sheet is complete.** The Meeting helper moves to **Ctrl+Shift+E** (⇧⌘E on a Mac), so Ctrl+Enter is no longer also its key (in the sidebar chat box it could open the helper instead of sending). The sheet now lists every shortcut Lumen handles, grouped into Tabs, Navigation, This page, AI, New tab page, Chat page and Lumen, with one line explaining that a site which uses a key itself (Google Docs, VS Code for the web) gets it first. The ⋯ menu shows the sidebar and Bookmark all tabs shortcuts, and the Meeting helper button and its box no longer show the placeholder "Mod+Enter".
- **One group and one phrase for the tabs the AI opened.** Settings > AI has an **AI tabs** group: **Hide AI tabs**, **When the AI finishes** (Leave open, Ask or Close) and **Bring tabs the AI opened to the front**. The menus, the right-click menu, the taskbar task and the chat list all say "tabs the AI opened" now. A hidden tab that needs you shows "1 needs you" on the Hide button, and a click shows it. The button opens its menu from the keyboard (Menu key or Shift+F10).

- **Right-click the sidebar's Hide AI tabs button to close the AI's tabs.** The menu has the Hide switch and **Close tabs the AI opened (N)**, which closes them in every window with Undo (the same as the menus' Close Tabs Opened by AI). With none left it says so.
- **Projects get a real folder, their chats are saved there as Markdown, and the AI can work in a folder.** Creating a project makes `DocumentsLumen Projects<name>` (or pick an existing folder; change the parent in Settings > AI > Projects folder). Chats in the project are written into its `Chats` folder as `<date> <title>.md` with a small header (title, dates, model, chat id), a couple of seconds after they change, without ever pausing Lumen; renaming a chat renames its file, moving it out of the project or deleting it moves the file to `ChatsRemoved` or `ChatsDeleted` and never erases it. These files are plain text, not encrypted (the project settings say so, and each project can turn it off); chats outside projects are still only saved encrypted. A missing folder shows "Folder missing" with Locate and Recreate, renaming a project offers to rename its folder, and deleting a project never touches its folder. **Work in folder…** (More menu, and a project's working folder) tells the AI where to work: Lumen's file listing defaults to it, and Claude Code, Codex, Grok Build and Antigravity start in it (Claude Code gets its file tools for that folder only).
- **The preview in Settings > Home now shows your whole new-tab page, and light backgrounds are readable in it.** On pastel gradients (Peach, Lavender, Mint...) and the light solids the preview's clock, greeting and date were white on a light picture; they are now dark, the way the real page draws them (one shared rule in `features/backgrounds.js`, so the two cannot disagree). The preview is also a small copy of your page: it takes your accent (also Match wallpaper), the animated effect running live at a small scale with its color, amount, speed and size (one still frame with Reduce motion or Performance mode, and a calmer one with Graphics: Light), the clock's style, size and card, the greeting's font and your name as you type it, the search box's width, the widget glass (Frosted, Clear, Solid) on three sample cards, and the light or dark theme. Pointing at a background (or an effect) tile swaps only that, keeping your other choices. The preview draws nothing while it is offscreen or Settings is hidden. The background tiles' labels on light backgrounds are dark in the dark theme too. `test/settings-preview.js` checks every background in both themes for the page's text mode and for WCAG AA contrast.

- **Saving a chat no longer holds Lumen up.** Each save of a long chat (400 messages) used to block the main thread for 14 to 31 ms: it wrote, renamed and re-read files synchronously, and rebuilt and re-encrypted the chat index every time. Saves are now written in the background (a temp file, then one rename, one write at a time per file), merged when they come in quick succession, cut into short slices, and the index is written once, and only if it changed; opening a chat from the history reads it in the background too. Quitting still writes everything that is pending before Lumen closes.
- **Settings opens about five times faster.** The first page used to appear after about a second (it waited for every section, and for the AI tools to be probed); now it appears in about 0.2 s. Only the page you open is built first and the rest while you look at it (search still covers everything), the page loads as one script and one stylesheet instead of 22 files, its first questions to the app are asked while it loads, the "is Lumen your default browser" check and the AI tool version checks no longer hold the app up, and checks that start programs wait until the page is on screen.

- **Lumen runs well without graphics acceleration too.** With graphics acceleration off (the setting, safe drawing mode, or Chromium falling back to software after GPU crashes), Visual effects: Automatic now means Light plus a software level: the new-tab background is one still frame, no blur anywhere, no blurred shadows or hover glows, short transitions, and the sidebar opens without a page snapshot (a snapshot is a CPU readback in software). If drawing falls to software mid-session, the pages switch at once, before the restart the notice offers. Full, chosen by hand, still keeps every effect. Settings says what is on right now and offers a Restart, and after a safe-drawing restart a strip says so.
- **Lumen is lighter on an integrated GPU.** A new **Visual effects** setting (Settings > System: Automatic, Full or Light) drops the backdrop blur behind glass surfaces (the chat box, new-tab cards and clock card, popups), stops the new-tab background drifting, and runs the new-tab effect lighter (half the particles, a smaller canvas, 20 frames a second, a rest after 20 seconds without input). Automatic picks Light on an integrated GPU (Intel, AMD APU) and is decided once at start-up, so it does not follow power changes. The look stays: cards use a flat, slightly denser tint instead of blur, and particles are still particles.

## 0.5.35 (2026-10-14)

- **Lumen now rides out graphics-driver resets.** When the graphics driver resets (Windows "display driver stopped responding"), Lumen logs it (reasons and times only, in `diagnostics/gpu-events.jsonl`), leaves the GPU alone for 10 seconds (the new-tab animation pauses and the sidebar changes without a page snapshot; once per 3 minutes at most), keeps WebGL working in maps and canvases afterwards, and, if drawing fell back to slow software mode, shows one notice with a Restart button (your tabs come back). A power source that flips every few seconds no longer switches Performance mode on and off: battery-saver and thermal limits must hold 15 seconds to turn it on and 60 seconds to turn it off, one switch per 2 minutes at most. Lumen also keeps Chromium from giving up on the GPU after a few driver crashes (it used to fall back to slow software drawing for the rest of the session); if the driver fails six times in two minutes, a notice offers a safe drawing mode for that session only.
- **Lumen is lighter on an integrated GPU.** A new **Graphics** setting (Settings > System: Automatic, Full effects or Light) drops the backdrop blur behind glass surfaces (the chat box, new-tab cards and clock card, popups), stops the new-tab background drifting, and runs the new-tab effect lighter (half the particles, a smaller canvas, 20 frames a second, a rest after 20 seconds without input). Automatic picks Light on an integrated GPU (Intel, AMD APU) and is decided once at start-up, so it does not follow power changes. The look stays: cards use a flat, slightly denser tint instead of blur, and particles are still particles.

## 0.5.34 (2026-10-14)

- **Lumen froze for up to 30 seconds at a time ("not responding", the window could not even be moved) when you opened the sidebar, switched or closed tabs, or clicked into the window.** The chat history index can list chats whose files are no longer there (moved to a backup folder, lost by a sync client). Each time Lumen listed your chats, which the sidebar, every tab switch and tab close and every window focus ask for, it waited 25 ms for each missing file and up to 120 ms more trying to read it for its title, on the main thread. With a couple of hundred such entries that was about 30 seconds of a frozen app, every time. Missing files are no longer waited for: on a test index of 300 entries with 296 files gone, listing took 9.5 s and now takes 9 ms, and searching chats went from 9.7 s to 3 ms. The missing chats still show as missing, and a chat whose file is there loads as before. Found by reading the frozen thread's call stack on the affected PC.
- **Freezes now name their cause.** If Lumen stops answering for a second or more, a small watcher thread writes what the main process was doing (fixed names such as `ipc:view:freeze` or `layout`, never a page address or title) to `diagnostics/hangs.jsonl` in Lumen's data folder, with how long it lasted; it keeps the last 200. It is always on and costs about 0.1 microsecond per recorded step.
- **Lumen stopped responding on big pages (Canvas and others) when you opened the sidebar or clicked between the page and the chat.** Windows showed "Lumen is not responding" for seconds at a time. The cause was not the sidebar itself: a program that reads windows through Windows' accessibility interface (here 1Password's desktop app; Phone Link and text tools do the same) makes Chromium build a full accessibility tree of every page, with a box for each run of text. On a big page that tree was rebuilt on every focus change, sidebar open or close and window switch, which kept the page busy and the main process waiting, 1.5 to 1.8 seconds per change on a 50,000-element test page. New **Settings > Appearance > Accessibility > Screen reader support**: on **Automatic** (the default), accessibility switched on by another program is kept to Lumen's own buttons and menus unless a screen reader is running (Narrator, NVDA, JAWS, ZoomText, Dolphin, or VoiceOver on a Mac); a screen reader started later gets the full support back. The same test page now stalls at most 67 ms. **On** keeps full support for a screen reader Lumen does not recognise, **Off** turns it off. The AI still reads pages as before, through its own route. 1Password keeps filling in pages through its browser extension.
- **The page froze or went blank when the sidebar opened or closed.** Since 0.5.33, opening or closing the AI sidebar (and, with the sidebar open, moving between the chat box, the page and other windows) could leave the page you were on frozen on its last picture, or blank, until you switched tabs. While the sidebar slides, Lumen hides the page for a moment behind a still picture of it. 0.5.33 had started resetting a page's background state every time its view was hidden and shown (the fix for black video after a tab switch), and changing that state on a hidden page tells Chromium the page is showing, so when the view came back it drew nothing new. The reset now happens only on a real tab switch; a page hidden for a moment by the sidebar or the full-page chat is left alone. Video after a tab switch still works (`test/video-frames.js`).
- **The tab strip could start empty.** Now and then, when Lumen opened with tabs from your last session, the window came up with no tabs shown in the strip (the pages were open behind it, but you could not see or click their tabs) until something changed a tab. Lumen skipped sending the strip its first list when the tabs had finished restoring before the window finished loading, treating the list as already delivered. It now always sends the strip its first list once the window has loaded.

## 0.5.33 (2026-10-14)

- **Thirteen accent colours, and "Match wallpaper".** Settings > Appearance > Accent color now offers Rose, Amber, Lime and Cyan beside the nine it had, a **Match wallpaper** choice (the accent comes from the new-tab background: a picture's dominant colour, or a gradient's own) and any colour you pick. Every colour is worked out in OKLCH for light and for dark and fitted to the contrast rules, so a choice can no longer make text unreadable: the accent as text is at least 4.5:1 on every surface (also on its own tinted chip), white on a button in the accent is at least 4.5:1, and the accent as a focus ring or icon at least 3:1. A colour that already passes (Blue) is used as it is; one that does not (Orange, Teal, Lime, Amber, most custom colours on the white theme) keeps its hue and gets deeper or lighter. The accent used to colour only the buttons and the selected tab: links and chips stayed blue in every other accent. It now reaches **every page of Lumen's own** the moment you choose it: the window, Settings, the chat page, the PDF viewer, history, downloads, the error pages, the new-tab page and the small popups (one stylesheet is put into each page; websites are never touched). I also found that Settings, the PDF viewer and the other plain pages never defined the colour of text on a button (`--on-accent`), so a primary button's text was the page's dark text colour on blue; it is white now. I left out surface-tinted whole-theme presets (Midnight, Nord, Solarized, Rosé, Forest): the app draws on about forty stylesheets that each define their own surfaces, popups cannot even link the shared tokens, and a tinted surface would need the text, borders and shadows of every one of them re-checked; the accents stay the one thing that changes colour across the app.
- **More new-tab backgrounds, grouped, with a live preview.** Sixteen new gradients (eight made for white text: Nebula, Midnight, Ember, Deep sea, Northern lights, Plum, Moss, Cobalt; eight pastel ones made for dark text: Peach, Lavender, Mint, Skylight, Sand, Blush, Citrus, Fog) and eight new solid tones (Ink, Slate, Navy, Pine, Wine, Paper, Cloud, Sage), all drawn in CSS, so nothing is bundled, downloaded or heavier than before. The picker in Settings > Appearance > Background has Gradients, Solids and Your picture sections, thumbnails, and a small preview of the page (clock, greeting, search box) that follows the pointer or the keyboard over the tiles before you choose. **Shuffle daily** picks a new gradient each day, the same one all day and never the same twice running. A light background turns the page's text dark and the cards white glass, in either system theme; a test applies every background, in light and dark, and checks that the top of the page shows it (not black) and that the clock, greeting and date meet WCAG AA on the pixels behind them. No photographs are bundled (CSS art costs the installer nothing).
- **Three new soft animated effects: Aurora drift, Soft blobs and Film grain**, beside Particles, Stars, Bubbles and Snow, and the effect picker shows a still picture of each. They are drawn on a canvas half the page's size (15 frames a second for the drifts, 8 for the grain), stop while the tab is not in front, draw one still frame with Reduce motion, and never run a timer while the page is hidden.

- **The AI reads pages with fewer tokens.** Measured on Wikipedia, Hacker News, MDN, example.com and news articles: a full `read_page` is now the page text plus an element count (about 55-75% smaller; `elements:true` lists the elements, with shorter links); `navigate` and `open_tab` return a short head of the page (title, URL, about 600 characters), so the AI often needs no extra read; a plain question ("What is the capital of France?") is sent without the page's text; and the page text sent with a message prefers the page's main content and leaves out menus and boilerplate ("Jump to content", "Main menu", Wikipedia's Appearance settings). Fixed: the compact page outline collapsed table layouts (Hacker News's 30 stories came out as 3 lines); it now lists each story.
- **Faster, leaner AI loop.** Once a chat passes the 60k-token mark, page text attached to older messages is cut to its title and address (about 80% less for a page-heavy chat; the prompt cache is untouched before that). Identical read-only calls repeated with nothing done in between (find, list tabs, web search, read URLs) get a one-line answer instead of running again, and a third identical read now gets an early nudge. Replies stream in 16 ms batches instead of one message per token, and long replies no longer rescan their whole text each frame (a 10,000-token stream went from about 1 s of scanning to 4 ms). Sign-offs like "thanks" go to the fastest model even after a hard task. Independent reads in one turn already ran together; this is now covered by tests. Max steps stays Unlimited by default.
- **Faster page actions for the AI.** Navigating, going back or forward, reloading, scrolling, hovering and reading several pages at once no longer sit out fixed pauses. After a page loads, Lumen waits only until the page stops changing (at most about 0.4 s), and a scroll returns as soon as the page has stopped moving. A simple page now opens in about 0.2 s instead of 0.65 s, a scroll takes about 0.05 s instead of 0.3 s, and a hover about 0.1 s instead of 0.5 s.
- **Pages load a little faster.** Lumen now asks the network hooks about far fewer requests: the ad blocker no longer sees your own local servers (localhost, 127.0.0.1) or Lumen's internal addresses, it is out of the way completely when switched off (Safe Browsing's check stays, on pages only), response headers are read on pages and frames only, and the Accept-Language header is set once instead of on every request. Sites that load hundreds of small files, like GitHub or Wikipedia, benefit most.
- **A lighter start-up.** Lumen reads about 25 fewer code files before its first window: the new-tab widget cards (Todoist, Gmail, weather, Spotify and the rest) load when a card of that kind is drawn, the extension libraries load once the window is being made, and a few menu dialogs (Page info, Keyboard Shortcuts, What's new) load when opened. The app is also about 1 MB smaller, without the duplicate module copies it never used.
- **Organize Tabs finds more of what belongs together.** A larger test set (21 sessions: students, developers, shoppers, researchers, mixed languages, one site with many topics, near-duplicate tabs, bare titles, sessions of 60 and 100 tabs) now scores the grouping: tabs that belong together and were grouped went from 64% to 82% with no more wrong groups. A roundup such as "Best laptops" joins the group about laptops, a tab that is only "Iceland" or "Metro map - Paris" joins the trip to that place, "coffee" and "caffeine" (and a few other words that mean one another) count as one word, a title that begins with the site's own name ("Louvre Museum tickets") is no longer read as just that name, two topics that share only "programming" (Postgres and React) stay two groups, trips to different places stay apart, and a few more subjects (financial aid, elections, motor racing, PC hardware, biology) are recognised. With AI on, the model's request is clearer (what each answer key means, when to leave a tab loose, how to name a group, an example), and a name you gave a kind of group before wins over the model's rename. `node scripts/eval-organize-ai.js` scores the AI step against cached answers of Claude Code's Haiku (no calls unless you pass `--live`).
- **Organize Tabs shows its groups sooner and groups a little better.** With AI on, the groups used to wait for Lumen to check how to reach the model (a signed-in Claude Code check can take a second or more); now they appear at once and the check runs alongside. The model still only refines them. Better grouping: a story three sites all cover ("earthquake") is a group, a news wire's name (Reuters) no longer pulls an unrelated story into a Finance group, a quarter's name (Q3) groups its docs, chat and spreadsheet, and a project's home page titled by its name alone goes with the project's other pages. Undo, pinned tabs and your own groups work as before.
- **Site permissions now behave as they do in Chrome.** After you clicked Allow, the site's own code still read the permission as "denied" (`Notification.permission`, `navigator.permissions.query`), so it carried on as if you had refused; the same went for private windows. Fixed. Before you decide, a site now sees "ask" (Notification "default", query "prompt") for location, notifications, camera, microphone and clipboard, instead of "denied", so sites actually offer to ask, and they hear about your answer straight away. Screen wake lock, motion sensors, background sync and payment handlers are allowed without a prompt, as in Chrome, and embedded players can request storage access (unless you block third-party cookies). Voice-input buttons that could never work (speech recognition) no longer appear on sites that check for it first.
- **Service workers work.** A page's `navigator.serviceWorker.register()` never finished in Lumen, so web apps that install a service worker (PWAs, push notifications, anything waiting on `serviceWorker.ready`) stayed stuck. The step that gives every page Chrome's identity left the worker waiting for it; the worker now starts at once and still reports Chrome's User-Agent.
- **Easier to drag the window.** The title bar always has somewhere to grab now: a strip of at least 56 px at the end of the tab strip stays put however many tabs are open (they scroll instead of filling it), and the empty parts of the toolbar (around the back and forward buttons, and left of the right-hand buttons) move the window too, while buttons and the address field still click. Double-click on any of them maximizes or restores the window. Dragging the only tab of a window still moves the whole window.
- **Codex driving Lumen is more reliable.** "Add to Codex CLI" now also sets longer time limits in `config.toml` (Codex's own 10-second start-up and 60-second tool-call limits cut off Lumen's start or an approval card you were still reading), the "driven by" pill and the sidebar steps say **Codex** whatever name the client sends, and read-only tools are marked as such, so Codex doesn't stop to ask before reading a page.
- **Faster, steadier agent connections.** An AI agent that connects to Lumen (Claude Code, Codex and others) now has its own Lumen window made, behind yours, as soon as it lists Lumen's tools, so its first page load is about 1 s quicker (it used to wait for the window). Lumen's local server for the sidebar's Claude Code and Grok Build no longer drops a connection that sat idle for more than 5 seconds while the model was thinking, which could lose a tool call. **wait_for** now matches text regardless of line breaks, extra spaces or non-breaking spaces.
- **Lighter for AI agents connecting over MCP.** `read_page` with no mode gives the compact outline, the server's start-up note and tool annotations are shorter, and the page savings above apply to every agent.
